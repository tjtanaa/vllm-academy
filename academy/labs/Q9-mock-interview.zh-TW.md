# Q9 · 模擬面試：演練推論工程師的面試流程

**需要：** Discord（有朋友和語音頻道會更好） · **時間：** 每週一次，每次 30 分鐘 · **單元：** E25，以及每一集的「Say it like a pro」 · **XP：** +75（每次 `/mock` 最多再加 +100）
**[English](Q9-mock-interview.md)**

推論工程師的面試問題，總是繞著同幾個主題打轉：記憶體計算、批次處理與排程、快取、平行化、效能量測，外加一題系統設計。光是知道答案還不夠，你得在兩分鐘內把它*清楚地說出來*。這個實驗就是每週一次的演練循環。

## 1. 先用一題暖身

選好你的程度。在看任何解答**之前**，先大聲回答，限時兩分鐘，計時器開起來。回答完再公開重點、追問方向和地雷（red flag）。

```text
/interview level:Junior
/interview level:Mid kind:Design
```

> ✅ **檢查點：** 你已經大聲說出一個答案，而且能指出一個自己漏掉的重點。

## 2. 學會系統設計的骨架

大多數 serving 系統設計題，都可以用同樣的五個步驟來回答。把這個骨架練到變成反射動作。

```text
1. 釐清需求：模型、context 長度、流量（QPS、突發程度）、SLO（TTFT、ITL、p99）、成本
2. 記憶體：權重 + KV × context × 並行數 → 需要幾張 GPU、用哪種平行化（E07、E19）
3. 引擎：batching、chunked prefill、prefix caching、量化、spec decode（S2、S4）
4. 機群：路由（cache-aware）、自動擴縮（小心冷啟動！）、必要時做 P/D 分離（E20、E28）
5. 量測：你會對什麼做 benchmark、對什麼設警報（E24）
```

> ✅ **檢查點：** 你不看資料，也能把這五個步驟寫出來。

## 3. 現場做記憶體計算

每一個設計題的答案，都離不開第 2 步。拿計算機反覆練習，直到你可以在紙上算出來為止。

```text
/kvcalc model:llama-3.1-70b context:32768 gpu:H100 gpus:4 users:16
```

> ✅ **檢查點：** 在機器人公布答案*之前*，你就先預測了 16 位使用者放不放得下，而且猜對了（或是你知道自己為什麼猜錯）。

## 4. 完整跑一場模擬面試

五道題，會計分。請誠實地自我評分：「Partial」是最有用的按鈕。機器人會保留你的最佳成績，拿到 80% 以上就能獲得 🎤 **Interview Ready** 徽章。

```text
/mock level:Mid
```

> ✅ **檢查點：** 你已經完成一場模擬面試，並寫下表現最弱的兩題，作為本週的複習重點。

## 5. 補強你的弱點

針對每一道答不好的題目，打開它連結的單元，重讀「🎤 Say it like a pro」的範例答案，然後錄下自己用 60 秒講一遍的版本。回放來聽，刪掉贅詞，再加進一個具體的數字。

```text
/episode episode:E17
```

> ✅ **檢查點：** 你的 60 秒答案裡，有一個機制、一個數字和一個取捨（trade-off）。

## 6. 準備你的專案故事

面試一定會問「說說你做過的東西」。可以拿你的 Q5 引擎、Q7 benchmark 或 Q8 的 PR 來講，並依照這個結構：情境 → 你做了什麼 → 量測到的結果 → 如果重來會怎麼改進。

```text
「我在 Qwen3-8B 上測了 prefix caching（Q7）。在 75% 前綴共用的工作負載下，TTFT p99 下降了 X%，
但在完全沒有共用前綴時沒有任何進步，所以我只會在 prompt 確實共用前綴的場景才開啟它。」
```

> ✅ **檢查點：** 你準備好兩個故事，每個都在 90 秒以內，而且每個都帶有一個數字。

## 7. 找真人來模擬

在語音頻道裡找個夥伴配對。一個人用 `/interview` 的題目和追問來當面試官，另一個人負責回答，有膽量的話就開著鏡頭。15 分鐘後交換角色。最後互相給對方一個「保持」和一個「調整」。

```text
#mock-interviews  ← post "LFG mock, Mid level, 21:00" and find a partner
```

> ✅ **檢查點：** 你已經給過一次回饋，也收到一次回饋。之後每週都重複一遍，你在 `/profile` 裡的分數應該會穩定上升。

## 學到了什麼

- 一個好答案有機制、有數字、有取捨，還有你早就預見的追問。
- 設計骨架（釐清需求 → 記憶體 → 引擎 → 機群 → 量測）能避免你講得離題。
- 模擬面試就是練習的次數。每週練習，勝過臨時抱佛腳一次衝刺。
